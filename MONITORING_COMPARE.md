# Compare: что сделано, как это устроено и куда развивать

Записано 25.08 по итогам переработки режима сравнения. Здесь три вещи: что режим умеет
сейчас, разбор вопроса «а можно ли сравнивать фичер-дрифт по периодам» (можно, но это
два разных вопроса — см. ниже) и список идей с оценкой, что из них стоит делать.

---

## 1. Что сделано

### UX

- **Кнопка вместо сегментов.** Compare убран из глобального ряда контролов и стал
  кнопкой — крайней в ряду, после сгруппированных Refresh + Auto. Активный режим —
  залитая кнопка.
- **Сайдбар настройки.** Кнопка открывает drawer (тот же, что у алертов) с тремя
  режимами-карточками:
  - **Off** — только выбранное окно, без базы;
  - **Previous period** — отрезок той же длины встык перед текущим окном;
  - **Custom period** — **два** календаря: первый период становится окном страницы,
    второй — базой сравнения. Оба с точностью до минут, кап 30 дней (ретеншен).
    Применяются вместе, одной перезагрузкой.
- **Индикация режима.** Пока сравнение включено, под контролами висит синяя плашка
  «Comparing with …» с датами (или «the previous period») и крестиком — крестик разом
  гасит режим на всех вкладках.

### Где сравнение применяется

| Вкладка | Что показывает в режиме Compare |
| --- | --- |
| Overview | дельты на карточках (requests, error rate, latency p95) |
| Runtime | дельты на всех 8 карточках + **ghost-линия**: пунктирный серый контур сравниваемого периода на каждом графике |
| Feature drift | PSI-дельта на каждой строке рейтинга (красным рост, зелёным спад) |
| Output drift | дельта PSI в headline |
| Data quality | дельта по каждой проверке в каждой строке таблицы (missing / type errors / range‑unseen, в п.п.) |
| Traces, Alerts, Reference profile | не применяется — сравнивать нечего |

### Механика (Query API)

- `compare=off|previous|custom` (+ `compare_start`/`compare_end` для custom;
  валидация 422: оба или ни одного, конец позже начала, не шире 31 дня).
  Легаси-значение `compare=reference` принимается и означает то, чем всегда фактически
  было: без базы — дрейфовые метрики и так меряются против эталона.
- Базовый интервал резолвится в одном месте (`_baseline_bounds`): previous — от длины
  текущего окна (включая кастомное), custom — как задано. Дальше одна механика кормит
  всё: rollup событий для карточек, серии для ghost-линий, историю
  материализованных окон для табличных дельт.
- **Ghost-линии**: в режиме сравнения оба периода кладутся на одну фиксированную
  сетку бакетов (авто-зум отключается — он ломал наложение), baseline сдвигается на
  ось текущего окна и уезжает в поле `baseline` каждой серии.
- **Табличные дельты** (drift/DQ): база = **среднее по материализованным 5-минутным
  окнам** сравниваемого периода. Среднее, а не какое-то одно окно: какое окно попало
  на край периода — шум, типичный уровень за период — сигнал.
  Для этого `fetch_result_history` научился верхней границе `until` (Greptime и
  in-memory стор).

### Известные оговорки

- Если сравниваемый период упирается в горизонт ретеншена (30 дней), его данные
  частично или целиком стёрты — дельта тогда сравнивает с «недобитым» периодом, и UI
  это пока никак не помечает.
- В custom-режиме плашка называет только второй период; первый виден в лейбле
  Window-контрола.

## 2. Вопрос: «а фичер-дрифт по периодам сравнивать выйдет?»

Выйдет — но «сравнить дрейф по периодам» значит две разные вещи, и путать их нельзя.

**Вопрос 1: «дрейфит ли модель сильнее, чем дрейфила тогда?»** — это сравнение двух
*уровней дрейфа*, каждый померен против обучающего эталона:
`PSI(период А vs reference) − PSI(период Б vs reference)`. Именно это уже сделано
(дельты в рейтинге фич). Считается дёшево из готовых материализованных окон.

**Вопрос 2: «изменился ли сам вход между этими двумя отрезками?»** — это прямое
сравнение распределений периодов между собой: `PSI(период А vs период Б)`, эталон не
участвует. Из имеющихся чисел **не выводится**: две маленькие дельты против эталона
могут скрывать большой сдвиг между периодами, если оба ушли от эталона в разные
стороны. Технически выполнимо — сырые события хранят inputs, бинны есть в reference
profile, гистограммы обоих периодов считаются на лету — но это новый вычислительный
путь по сырым событиям в query-сервисе, и на 30-дневных периодах он уже не бесплатный.

**Решение (обсуждено 25.08): вопрос 2 нужен, но не третьим числом, а картинкой.**
Ещё один PSI на вкладке, где PSI уже означает «против эталона», запутает. Правильная
форма — в детальной панели фичи, где уже рисуется гистограмма «reference vs current»,
в режиме Compare добавить **третий контур: распределение сравниваемого периода**.
Дельты в списке отвечают «где смотреть», оверлей гистограммы — «что именно произошло».
То же самое напрашивается для гистограммы Output drift.

## 3. Идеи дальше (в порядке убывания ценность/усилия)

1. **Оверлей распределения периода Б** в детальной панели фичи и в гистограмме Output
   drift (см. выше). Закрывает «вопрос 2» без нового термина. Усилия умеренные:
   гистограмма по сырым событиям сравниваемого периода на биннах референса.
2. **Пометка «неполное сравнение»** — когда базовый период (previous или custom)
   частично за горизонтом ретеншена или в нём заметно меньше данных, чем в текущем.
   Дешёвая честность: одна проверка границ + бейдж на плашке.
3. **Ghost-линии на трендовых графиках дрейфа** (psi_over_time, mean confidence,
   class share): та же механика сдвига оси, что у Runtime, источник — история окон
   базового периода. Средние усилия.
4. **Compare в машинном API и SDK**: `compare*`-параметры уже принимаются машинными
   маршрутами (общая зависимость), но SDK их не прокидывает и докстринги молчат.
   Малые усилия, делать при следующем заходе в SDK.
5. **Пресеты периодов** в сайдбаре custom-режима («прошлая неделя», «тот же день
   неделю назад») — сахар поверх готового, когда дойдут руки до полировки.
6. **Дельта near-threshold и per-class вероятностей** на Output drift — сравнение
   вероятностных блоков между периодами. Нишевое, ждёт реального запроса.

Не делаем сознательно: третий «PSI между периодами» как число в таблицах (путает);
сравнение более двух периодов сразу (не тот инструмент).
